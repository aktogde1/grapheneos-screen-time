# GrapheneOS Screen Time

Локальная панель экранного времени Android / GrapheneOS: дни, активность приложений, категории и экспорт таблицы CSV. Работает на компьютере, читает доступную историю телефона через ADB и открывается в браузере.

**Не нужны root, разблокировка загрузчика, Android Studio или установка приложения на телефон.** Python использует только стандартную библиотеку: `pip install` не требуется. Это независимый проект, не официальный продукт GrapheneOS.

## Первый запуск — по порядку

### 1. Подготовьте ADB и Python на компьютере

1. Скачайте **Android SDK Platform-Tools** для своей ОС с [официальной страницы Google](https://developer.android.com/tools/releases/platform-tools). Распакуйте ZIP в постоянную папку, например `platform-tools` в домашней папке. Внутри будет `adb.exe` на Windows или `adb` на macOS / Linux. Установка Android Studio не требуется.
2. Добавьте эту папку в `PATH` или используйте полный путь к ADB с параметром `--adb`. Проверка: `adb version`. На Windows в PowerShell из папки Platform-Tools используйте `./adb.exe version`; на macOS / Linux — `./adb version`.
3. Установите [Python](https://www.python.org/downloads/) **3.10 или новее** и проверьте `python --version`. Если ваша ОС использует команду `python3`, замените `python` на `python3` во всех примерах ниже. На Windows можно использовать `py -3`, предварительно проверив его версию.

ADB и Python устанавливаются **вручную**. Установщик этой панели не скачивает их, не меняет `PATH`, не устанавливает драйверы и не требует прав администратора. Windows иногда требует USB-драйвер устройства, Linux — правил `udev` / разрешений на USB: см. [официальную инструкцию подключения](https://developer.android.com/studio/run/device). Не запускайте всю панель от администратора / root для обхода проблемы.

### 2. Включите отладку на телефоне

1. Откройте **Настройки → О телефоне → Номер сборки**.
2. Нажмите на **Номер сборки семь раз**, при запросе подтвердите разблокировку телефона. Появятся параметры разработчика.
3. Откройте **Настройки → Система → Для разработчиков** и включите **Отладка по USB**. Названия меню могут немного отличаться.
4. Подключите телефон к компьютеру **USB-кабелем с передачей данных**. Кабель «только зарядка» не подходит.
5. **Разблокируйте телефон**. При запросе «Разрешить отладку по USB?» подтвердите RSA-ключ только своего доверенного компьютера. Не отмечайте постоянное разрешение для чужого компьютера.

В GrapheneOS проверьте **Настройки → Безопасность → Защита от эксплойтов → USB-C port** (на некоторых устройствах — `USB-C port and pogo pins`). Защита порта может блокировать новые подключения, когда телефон заблокирован. Сначала разблокируйте телефон и переподключите кабель. Для ADB нужен режим, разрешающий USB-данные при разблокированном телефоне; `Off` и постоянный `Charging-only` их не разрешают. Не отключайте все защиты: обычно достаточно штатного `Charging-only when locked`. Если временно меняли настройку, верните её после работы. [Описание режимов GrapheneOS](https://grapheneos.org/usage#usb-c-port).

### 3. Проверьте подключение

В терминале компьютера:

```text
adb devices
```

Если ADB не в `PATH`, запустите ту же команду из папки Platform-Tools:

```powershell
# Windows PowerShell
./adb.exe devices
```

```sh
# macOS / Linux
./adb devices
```

В списке рядом с идентификатором телефона должно быть **`device`** — не `unauthorized` и не `offline`. Не публикуйте сам идентификатор. Состояние `device` подтверждает подключение, но не гарантирует наличие достаточной истории использования.

### 4. Установите панель одной командой

После подготовки ADB и Python выполните из любой папки:

```sh
python -c "from pathlib import Path; import urllib.request, subprocess, sys; p = Path.home() / '.grapheneos-screen-time-install.py'; urllib.request.urlretrieve('https://raw.githubusercontent.com/aktogde1/grapheneos-screen-time/main/install.py', p); raise SystemExit(subprocess.call([sys.executable, str(p)]))"
```

Команда рассчитана на **публичный репозиторий `aktogde1/grapheneos-screen-time` с веткой `main`**. Она скачивает файл установщика в домашнюю папку, запускает его текущим Python, скачивает исходники панели по HTTPS и запускает `run.py`. Это установка **только панели**, а не ADB / Python. Вы запускаете код из репозитория: [прочитайте `install.py`](https://github.com/aktogde1/grapheneos-screen-time/blob/main/install.py) перед запуском. Ветка `main` меняется; для воспроизводимой установки используйте проверенный commit и соответствующий HTTPS URL архива.

Установщик выводит путь к коду и команду повторного запуска: на Windows — для **PowerShell** (копируйте вместе с начальным `&`), на macOS / Linux — для **POSIX shell**. Он не создаёт автозапуск, службы или задачи по расписанию. Терминал остаётся занят сервером — это нормально.

**Альтернатива без установщика:** скачайте [ZIP исходников](https://github.com/aktogde1/grapheneos-screen-time/archive/refs/heads/main.zip), распакуйте, откройте терминал в папке, где лежит `run.py`, и выполните:

```sh
python run.py
```

### 5. Соберите первый снимок

Откройте адрес, который напечатал сервер; по умолчанию это **http://127.0.0.1:8797**. Браузер открывается автоматически, если не указан `--no-browser`. Не открывайте `web/index.html` двойным щелчком: ему нужен локальный API.

Нажмите **«Обновить данные»**. Чтение ADB может занять время. Первый запуск без снимка показывает инструкцию, а не выдуманные показатели. После успешного сбора панель сохраняет локальный снимок. Подключение кабеля и перезагрузка страницы сами по себе новый сбор не запускают: обновление **ручное**.

Остановить сервер: **Ctrl+C** в терминале. Для следующего запуска повторите напечатанную установщиком команду или `python run.py` из папки исходников. После отключения телефона сохранённый снимок доступен при запущенном сервере, но для нового сбора телефон нужно подключить и авторизовать заново.

## Параметры запуска

```text
python run.py --help
python run.py --adb "PATH_TO_ADB" --serial DEVICE --user INTEGER --port INTEGER --no-browser --data-dir "PATH_TO_PRIVATE_DATA"
```

Значения `PATH_TO_ADB`, `DEVICE`, `INTEGER` и `PATH_TO_PRIVATE_DATA` — **заполнители**, их нужно заменить. Параметры необязательны и могут использоваться по отдельности.

| Параметр | Зачем |
| --- | --- |
| `--adb PATH` | Путь к уже установленному `adb` / `adb.exe`, если автоматический поиск его не нашёл. |
| `--serial DEVICE` | Явный идентификатор из `adb devices`, если подключено несколько устройств / эмуляторов. Не отправляйте его в issues. |
| `--user INTEGER` | Номер нужного профиля Android. По умолчанию — владелец (`0`), не обязательно активный профиль. Профили имеют отдельную историю. |
| `--port INTEGER` | Другой локальный порт, если стандартный занят. |
| `--no-browser` | Не открывать вкладку автоматически. Адрес остаётся в терминале. |
| `--data-dir PATH` | Отдельная приватная папка данных вне исходников и вне папки установленного кода. |

По умолчанию программа ищет ADB и одно авторизованное устройство автоматически. При нескольких устройствах выберите нужное через `--serial`; не полагайтесь на случайный выбор. Сервер слушает **только `127.0.0.1`**, не сеть Wi-Fi. `GET /api/health` — проверка принадлежности локального сервера этой панели. Если порт занят, прочитайте сообщение в терминале и при необходимости выберите другой порт; не завершайте чужие процессы вслепую.

## Если телефон не виден

| Симптом | Что проверить |
| --- | --- |
| `adb` не найден | Platform-Tools распакован? Проверьте полный путь и `adb version`, затем передайте `--adb`. В PowerShell локальный файл запускается с `./`. |
| Список `adb devices` пуст | Кабель поддерживает данные? Попробуйте другой кабель и USB-порт без хаба; разблокируйте телефон, проверьте отладку и защиту USB-C. При необходимости проверьте драйвер Windows / правила Linux по официальной инструкции. |
| `unauthorized` | Разблокируйте телефон и подтвердите RSA-запрос для доверенного компьютера. Если запроса нет, переподключите кабель. При необходимости отзовите разрешения отладки в параметрах разработчика и авторизуйте свой компьютер заново — это отзовёт и другие сохранённые разрешения. |
| `offline` | Переподключите кабель, разблокируйте телефон, обновите официальные Platform-Tools. Можно выполнить `adb kill-server`, затем `adb start-server` и `adb devices`; это прервёт другие текущие ADB-сессии. |
| Несколько устройств | Укажите `--serial DEVICE`, подставив нужный идентификатор из списка. |
| Телефон подключён, но данных мало | Проверьте профиль `--user`; доступная история Android ограничена и может быть короткой на новом устройстве. Недостающие дни нельзя восстановить задним числом. |
| После отключения / ошибки виден старый отчёт | Это последний сохранённый снимок, а не текущие данные. Проверьте время снимка и нажмите обновление после восстановления связи. |
| Браузер не открылся | Откройте напечатанный HTTP-адрес вручную и оставьте терминал с сервером открытым. |

## Данные и приватность

Снимки и пользовательские настройки хранятся **вне репозитория**:

| ОС | Приватные данные по умолчанию | Код при установке через `install.py` |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%/GrapheneOSScreenTime` | `%LOCALAPPDATA%/Programs/GrapheneOSScreenTime` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/grapheneos-screen-time` | `${XDG_DATA_HOME:-~/.local/share}/grapheneos-screen-time-app` |
| macOS | `~/Library/Application Support/GrapheneOSScreenTime` | `~/Applications/GrapheneOSScreenTime` |

В записи Linux используется обозначение переменной окружения / запасного пути, а не команда для копирования буквально. Параметр `--data-dir` меняет только расположение приватных данных; `--install-dir` установщика — только расположение кода.

Панель не отправляет статистику в облако, не использует внешнюю аналитику / CDN и не меняет настройки телефона. ADB-команды сбора — чтение; проект не получает root, не удаляет приложения и не устанавливает APK. Для скачивания проекта нужен интернет; сам сбор и просмотр локального отчёта не требуют облачного сервиса.

**USB debugging даёт компьютеру широкие полномочия**, даже если эта панель использует только чтение. Авторизуйте только доверенную машину. После использования выключите отладку по USB; если компьютер чужой или больше не доверенный — также **отзовите разрешения отладки по USB** в параметрах разработчика. Сохранённый снимок после этого остаётся на компьютере.

Отчёт может раскрывать названия приложений и привычки. Не добавляйте в Git снимки, сырой `dumpsys`, CSV-экспорты, серийные номера, скриншоты или личные пути. `.gitignore` — страховка, не очистка уже отслеживаемых файлов. Перед публичной отправкой проверяйте `git status` и diff. Приватную папку можно резервировать отдельно; удаление кода не удаляет её. Для полного удаления приватных данных остановите сервер и удалите эту папку **отдельно, осознанно**.

## Как читать показатели

- Отчёт охватывает доступные полные календарные дни перед сегодняшним днём, до семи; даты показаны в интерфейсе. Сегодня — отдельный неполный день и не входит в среднее за полные дни.
- Экранное время вычисляется по событиям экрана и блокировки, а не суммой времени приложений. «Разблокированный экран» и «Включённый экран» — разные оценки.
- Время приложений восстановлено по событиям активности и приблизительно. Музыка при выключенном экране и фоновые службы не означают экранную активность.
- Категории — группировка, а не оценка продуктивности. Их доли считаются от времени приложений, не от общего экранного времени. Неизвестные приложения могут отображаться как имена пакетов в категории «Прочее» (Other).
- Ноль / отсутствие записи за период не означает «никогда не пользовался». История Android ограничена, формат зависит от версии ОС; короткую или неполную историю нужно читать с учётом предупреждений панели.

## Обновление и управление установкой

**Сначала остановите сервер.** Повторите однострочную команду установки или запустите сохранённый установщик. Установщик скачивает новый ZIP, проверяет пути и распаковывает во временную папку рядом с кодом. Затем заменяет управляемую папку кода. Ошибка скачивания / проверки оставляет старый код на месте; при ошибке замены предпринимается откат, а при неудачном откате путь к сохранённому старому коду будет напечатан.

**Обновление заменяет все файлы установленного кода, включая ваши локальные правки.** Сохраните их заранее или работайте в отдельном Git checkout и запускайте `python run.py` оттуда. Приватные данные вне кода обновление не трогает. Никогда не помещайте `--data-dir` внутрь папки кода: установщик не может распознать произвольную приватную папку, которую вы туда положили.

Параметры установщика (не `run.py`):

```text
python install.py --help
python install.py --no-launch
python install.py --install-dir "PATH_TO_APP_CODE" --no-launch
python install.py --archive-url "HTTPS_URL_TO_REVIEWED_REPOSITORY_ZIP" --no-launch
```

Папка назначения должна быть новой / пустой или иметь метку предыдущей установки этой панели. Установщик отказывается заменять посторонние непустые папки, корень диска / домашнюю папку, размещать код внутри Git checkout или в стандартной приватной папке данных. Символические ссылки и опасные пути в ZIP отклоняются. Ограничения архива: 32 MiB при скачивании, 128 MiB распакованных файлов, 10 000 записей. HTTPS проверяется штатными сертификатами Python; проверка ZIP-путей **не является проверкой доверия к самому коду**. `--archive-url` используйте только для проверенного источника; HTTP разрешён лишь на loopback для локальных тестов. `--no-launch` устанавливает / обновляет код, но не запускает панель и не обращается к телефону.

## Проверка установщика без телефона

```sh
python docs/test_installer.py
```

Тесты используют только стандартную библиотеку, синтетические ZIP-файлы и HTTP-сервер на loopback. Они проверяют установку и обновление, сохранность отдельной приватной папки, отклонение zip-slip / ссылок / опасных имён, отказ от посторонних папок и сохранение старого кода при неудачном откате. Никакие реальные метрики, ADB-команды или программные установки не выполняются. Временные файлы создаются вне репозитория (переменная `TMPDIR` позволяет выбрать папку тестов).

## English quick start

Install Python 3.10+ and official Android Platform-Tools yourself. Enable Developer options with seven Build number taps, enable USB debugging, connect a data-capable USB cable, unlock the phone and approve your trusted computer's RSA prompt. Confirm `adb devices` reports `device`. On GrapheneOS, USB-C protection may block new connections while locked; unlock and reconnect instead of disabling all protections.

Download the repository ZIP and run `python run.py`, or use the one-line installer above after reviewing it. Open the printed loopback URL and click **Обновить данные** (Refresh data). Collection is manual; private snapshots stay outside the source tree. Use `--serial` for multiple devices and `--adb` for a non-PATH ADB installation. Turn off USB debugging afterward and revoke authorization for untrusted computers.
